# Dream · 领域知识整理

一份 AnySolvers 项目维护一个领域。每个 `runs/<task>/` 是一个研究问题，编号批次保存实验。领域 wiki 位于同一项目的 `dream/wiki/`。可直接在当前会话说「按 dream/DREAM.md，整合调度 003 和装箱 002 的开发发现，关注大实例超时」。这会启动一次文档整理，由当前会话完成判断和写作。

## 定位

首次使用时从框架目录执行：

```sh
.venv/bin/python -B dream/wiki.py init
```

首页在 `dream/wiki/README.md`，主题页在 `dream/wiki/topics/`。使用独立项目时，工具遵循现有的 `ANYSOLVERS_PROJECT_ROOT`，从该项目的 runs 取证，在该项目的 dream/wiki 写作。先读首页，搜索相关主题，读完整页，包括人工修订，再决定要解决的问题。

## 采集

按用户指定的任务和批次读取。以下 ID 是命令示例：

```sh
.venv/bin/python -B dream/sources.py scheduling/003
.venv/bin/python -B dream/sources.py scheduling/003 eval-a --cases
.venv/bin/python -B dream/sources.py scheduling/003 --report r1-r001
```

第一条列出公开发现、可用的已发布开发成绩和基线，以及已封存方法报告的会话名。第二条读取某次测量的逐例指标。指定要在领域内共享的方法报告时，带上 `--report`，查询其评测时也带同一选项。工具返回方法正文和关联的开发评测 ID。材料来自本地文件，工具不提交实验。作者的发现是当时的解释；写成实测发现时，查看当前测量的覆盖、有效性、probe 标志和失败情况。最终留出集和私有笔记不进入领域页。

## 整合

每个主题页用一个研究问题作标题。开头用一两句交代当前认识，正文用下面两个二级标题组织：

```markdown
# 什么时候值得缩小搜索邻域？

## 有证据的发现

在什么条件下观察到了什么结果？与哪个基线比较？[^a]

## 待验证的猜想

哪一种机制可能解释它？什么对照实验能区分另一种解释？
出现怎样的结果会使我们修订猜想？

[^a]: task/003 eval-a 这里粘贴工具返回的完整摘要哈希
```

优先修订原段落。相同发现补充独立来源；新反例出现时保留两边的条件，把原结论收窄；猜想只验证了一部分时，将已验证的观察移入发现，剩余机制留待验证。一次 Dream 可以得到空差异。主题分化为两个可以独立理解的问题时才拆页。

用 sources 返回的 `citation` 写脚注。来自指定方法报告的证据在脚注末尾附 `--report 会话ID`。复核旧引文时执行：

```sh
.venv/bin/python -B dream/sources.py scheduling/003 eval-a --expect SHA256
```

若原编号已重算，确认新结果后修订受影响的句子。若结果仍待重算，撤下失效成绩作为支撑的说法，在文中标明待复核。人可以直接修改 Markdown，或在会话中要求核查、记录异议和提出对照实验。

## 无证据思路

独立的领域 Dream 还要考虑现有实验尚未检验的机制、跨问题类比和可证伪预测。把有研究意义的无证据思路写进 `topics/无证据猜想-<研究问题>.md`；首页链接文字同样标明「无证据猜想」。同一问题优先更新原页。页面示例：

```markdown
# 无证据猜想：搜索预算应按实例结构分配吗？

## 无证据猜想

目前没有实验验证这个机制。我的猜想是……。它预测……。
可在相同算力下比较……和……；如果观察到……，就应放弃或收窄这个解释。
```

可以链接启发该思路的实测主题，在正文区分启发与验证。后来出现直接证据时，把受支持的具体观察写入有引用的主题页，从猜想页链接过去，并说明剩余未验证部分。

## 发布和索引

`read` 在标准输出返回正文，在标准错误返回本次读取的 SHA-256。把修改后的全文放在临时草稿中，用该摘要发布；首次创建页面使用 `new`。

```sh
.venv/bin/python -B dream/wiki.py read topics/限时搜索.md
.venv/bin/python -B dream/wiki.py write topics/限时搜索.md --expect SHA256 < /tmp/revised-topic.md
```

遇到版本冲突，重读并合并人工修改。再核对首页的相对链接；新增、移动主题时按同样方式更新首页。最后检查涉及的页面和引文，把实质变化告诉用户。例行整理不会产生按次数编号的文档。

## 在选择方法时引用

维护 wiki 与科研循环各自运行。研究员选择下一步方法时，可对单次 context 指定查询：

```sh
.venv/bin/python -B tools/research.py context scheduling/003 --session r1-r001 --wiki-query '邻域 超时'
```

协调者可以在 `tools/run.py iteration-context` 上使用相同选项。当前 selections 方法返回最多三个相关段落，含主题路径、发现或猜想的分类和脚注。没有传选项、wiki 尚未建立或没有命中时，上下文沿用原格式。研究员可采纳或跳过建议；本批正式迭代证据仍由本批开发测量提供。
