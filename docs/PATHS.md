# 实现与项目目录

默认实现和项目仍在同一目录。设置 `ANYSOLVERS_PROJECT_ROOT` 可让一套固定实现管理独立项目；该值在进程启动时解析为绝对路径，建议直接提供绝对路径。

- `tools/`、`modules/` 始终从当前执行的框架目录读取，项目中同名目录不能覆盖它们。
- 配置、task 输入及 `runs/` 始终相对项目根目录解析，不依赖调用命令的 cwd。独立项目需准备自己的配置和任务文件；不会隐式借用框架的示例任务。
- 运行内的候选、评测、起点和报告都采用运行相对路径。模块依赖仍严格限制在所属方法包内。
- 新批次保存 `implementation_sha`：全部固定通用工具与选定模块文件的内容摘要，加载时逐文件验证。参数、输入和预算另外绑定在配置摘要中。摘要不含安装目录，完整项目停止后搬迁不会改变运行身份。
- 这不是实现备份功能。升级应使用独立实现目录并创建新批次；旧批次需要保留原实现及配置。程序不自动复制公共说明、代码包或旧版本档案到 runs，也不修改已有封存批次。
- Docker 暂存目录使用系统临时目录（遵循 TMPDIR）；候选的固定镜像、单核、无网络与资源限制保持原合约。当前执行器仍依赖 POSIX 文件锁和定时器，不宣称支持 Windows 原生执行。

示例（配置与初始化已在独立项目中准备）：

```sh
ANYSOLVERS_PROJECT_ROOT='/absolute/path/to/project' /absolute/path/to/engine/.venv/bin/python -B /absolute/path/to/engine/tools/run.py check STUDY/001
```

搬迁前停止并核对原生会话及评测；该功能不迁移活跃进程，也不把未知回执转换为重新执行权限。
