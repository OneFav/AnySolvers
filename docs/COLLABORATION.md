# 笔记续接与共享发现协作

当前方法位于 `modules/research/notebook_collaboration/`，以会话内多次实验、跨会话笔记和共享发现/源码组织原生研究员。这里只描述这一具体方法，其他思想可作为独立方法包替换。

## 角色和模块

主会话通过 research 做启动、预算、续接、异常处置、最终检查；初始化与终局模块仍由主会话执行。研究员自行提出算法、写代码、直接调用评测工具、按需读取结果、保存笔记和发布发现。evaluation、selections 是确定性功能模块，不需要另起 agent，也不需要主会话逐次转发。

## 直接接口

所有调用：`.venv/bin/python -B tools/research.py OP STUDY/001 --session SESSION ...`。

| OP | 参数 | 返回与作用 |
| --- | --- | --- |
| context | 无 | 自己的历史与最新笔记、允许读取的开发证据、共享发现 ID、有效研究时间 research_time 与扣除预约后的预算；调用额度 null 表示不限 |
| evaluate | --manifest M --id R --dataset D [--evaluation E] [--probe] | 自动封存当前会话候选、预约预算、排队运行；直接返回响应和测量摘要 |
| result | --id R 或 --evaluation E；可加 --details / --case C | 默认摘要；详情仅访问自己、基线或明确公开的开发证据 |
| findings | 可加 --id F | 默认简短目录；指定 ID 返回完整公开发现及真实证据 |
| share | --file 草稿 | 自动验证 evidence_ids，保存作者解释与可信分数，附源码版本 |
| reuse | --file 草稿 | 对已公开源码登记来源，返回固定 source_file/SHA；可立即读取，无人工许可往返 |
| iteration | --file 算法想法 | 校验 author_session、开发证据和私有历史归属，登记下一代算法机制 |
| checkpoint | --file 笔记 | 保存本研究员学习/失败/未知、候选、证据、下一 iteration |
| audit | 不需 session | 协调者核验封存记录与未决请求 |

 evaluate 的请求 ID 最长54字符，evaluation 默认 R-eval。同请求同参数返回同一响应、不重复求解；同 ID 不同参数拒绝。CLI 不提供预算修改、begin/end-session、final、任意路径读取或程序执行功能。`session_id` 是协议身份，不是安全令牌；共用宿主权限的 agent 仍可能绕过接口，当前不宣称防恶意研究员的访问隔离。

## 排队、预算和异常

先核验调用进程对 Docker 的访问能力；前置检查失败不登记候选/请求/attempt，也不消耗评测额度。当前 Codex 的 exec 沙箱可能需平台批准 require_escalated 才可访问 Docker socket；这是进程权限，不是主会话转发。

提交在短状态锁内登记请求；evaluation_calls 默认 null 不限次数，设为有限额度时原子预留，多个研究员不能抢用最后一个额度。每会话同时最多一个未回应请求。最多三槽测量租约由进程持有；等待时不占元数据锁，研究员可读取发现、登记笔记。同快照请求互斥。程序没有额外后台调度器，不承诺严格 FIFO。等待单独写 admission_queue_wait_s，沙箱本身排队写 queue_wait_s，均不侵占单案与整次执行预算。

begin-session 登记后，主会话实际 spawn 并用 activate-session 绑定 native_id 才开始计时。默认每会话 2400 秒有效研究时间，扣除前置检查和请求到响应的评测区间并集；不得自报暂停，重复响应不会重复扣时。到期只拒绝新候选/评测，已有结果、笔记和 iteration 仍可读取或收尾，不杀模型进程。run_wall_s 默认 96 小时整批准入窗口，包含排队；与净研究时长不是同一个时钟。未决状态不会靠超时自动恢复，仍需核验。

同请求有独立互斥锁，防止重复调用并发求解。真正开始时重新核验会话、预算、候选、数据与冻结文件。测量已经留下未决 attempt、基础设施错误或清理不明时，后续测量拒绝；不能通过新 ID 跳过。已预约但未完成调用由主会话查看进程/锁/记录后处置，不自动重放。低层程序为主会话保留管理入口；研究员只使用直接 CLI。

明确在任何测量登记/attempt 前被拒绝的请求可返回 `status: not_started, evaluation: null`，其等待结束且不消耗评测次数；这不是成功成绩。无法确认是否已执行的错误仍保持未决，需要主会话核验。评测已封存而响应写入前中断时，只补回该真实响应，不再次求解。

## 记忆和共享

notebook 是私有交接单，iteration 是具体下一代算法想法；二者都由研究员直接登记。新原生会话读最新封存笔记，主会话不替研究员写算法。共享发现允许 result/hypothesis/insight/error/observation，result 必须引用已封存开发成绩；自然语言 claim 与可信测量分开。只公开引用过的证据，不默认开放作者全部实验、私有笔记或源码。引用别人的公开源码前登记 reuse，并将实际父源码写进 candidate.parent_id。

最小事实记录仍为候选、测量摘要/逐例证据、请求响应、必要笔记与实际共享来源；不复制公共提示词、完整聊天或 Skills。请求、响应、笔记、发现和复用位于本批 `research/exchange/`。

## 验证范围

单元测试检查排队、预算竞争、重复请求、数据范围与来源等；轻量真实运行检查模型是否实际自己调用工具并得到结果。背包例子属于机制验收，不证明新算法、新颖性或共享发现的因果效果。正式研究需要另行授权。
