# 持久化与人工协调恢复

通用 JSON 写入先同步临时文件、原子替换，再同步所在目录。研究 exchange 在落记录和状态之前持久化完整工具意图；评测逐例先记录 attempt 再执行，并在结果后同步 result。状态更新成功之前不会向调用者返回成功。

恢复接口只供主会话管理，不调用模型、不执行候选、不改变模型会话 ID、轮数或预算。96 小时准入窗口仍是原来的固定墙钟窗口，不新增服务故障扣时。

| 中断点 | 可执行的核对 |
| --- | --- |
| exchange 意图已写，元数据或状态尚未提交 | `tools/run.py reconcile-exchange RUN` 检查原身份与内容，将已验证的原始元数据补入状态；原时间戳保持不变 |
| 完成回执已写，评测摘要或状态封印尚未提交 | `tools/run.py reconcile-evaluation RUN --evaluation ID` 锁定原评测并校验回执、日志配对、配置及清理证明后补账 |
| 评测已封存，研究 response 尚未登记 | 研究员以原请求 ID 再次调用 evaluate，读取已有证据并补 response；不会启动第二次求解 |
| 只有 attempt，没有完整可信结果；缺失/损坏回执；基础设施或清理未知 | 保持阻塞，主会话核查现场；不能换 ID 或自动重放 |
| 起点文件写出，会话尚未提交 | 同 actor、轮次和相同来源的 begin-session 可采用完全相同的起点；冲突内容拒绝。此时未返回会话启动参数，不自动创建原生进程 |
| 方法报告文件写出，状态尚未提交 | 相同正文与可信事实可重新提交以登记原报告；内容不同则拒绝 |

工具意图、原始请求、完成回执和状态记录都不能手工改写来制造成功。没有提供强制解锁、结果猜测或预算补发接口。存储设备损坏仍需要独立备份；文件同步不能承诺任意硬件故障后数据一定存在。测试中的进程/写入中断和模拟评分不代表真实模型、Docker 或断电验收。
